# Как машина учится видеть

Веб-презентация мастер-класса по компьютерному зрению: путь от одного пикселя
до свёрточной нейронной сети и классификации рукописных цифр MNIST.

**Сайт:** https://nebolsinvasili.github.io/MS/

Статический сайт без бэкенда: 22 слайда, управление с клавиатуры и мыши,
режим обзора всех слайдов, полноэкранный режим. Сайт автономен — шрифты,
картинки и скрипты лежат локально, поэтому работает без интернета.

---

## Что нужно

| Способ | Требуется | Когда использовать |
|---|---|---|
| Docker | Docker + Docker Compose | показ в аудитории, работа без интернета |
| GitHub Pages | только браузер | раздать ссылку участникам заранее |
| Python | Python 3 | быстрый локальный просмотр без Docker |

Установка Docker (если ещё нет):

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # затем перелогиниться
```

Проверка, что всё встало:

```bash
docker --version && docker compose version
```

## Запуск через Docker

```bash
git clone git@github.com:nebolsinvasili/MS.git
cd MS
docker compose up -d --build
```

Сайт откроется на **http://localhost:8080**.

Первая сборка занимает 1–3 минуты (скачивается образ nginx), дальше — секунды.
Пересобирать (`--build`) нужно только после изменения файлов сайта.

Полезные команды:

```bash
docker compose ps                    # статус и порт
docker compose logs -f               # логи nginx
docker compose restart               # перезапуск
docker compose down                  # остановить и удалить контейнер
docker compose up -d --build         # пересобрать после правок
```

Контейнер называется `ms-deck` и имеет healthcheck: статус `healthy`
в `docker compose ps` означает, что nginx действительно отвечает.

## Порядок действий в день мастер-класса

### За день до

1. Собрать образ и убедиться, что сайт открывается:

   ```bash
   docker compose up -d --build
   curl -sS -o /dev/null -w "%{http_code}\n" http://localhost:8080/    # ждём 200
   ```

2. Проверить ссылку GitHub Pages в браузере — она должна открываться
   и на телефоне (мобильная вёрстка тоже поддерживается).

3. Уточнить IP ноутбука для локальной раздачи:

   ```bash
   ip -4 addr show scope global | grep -oP 'inet \K[\d.]+'
   ```

   Обычно что-то вида `192.168.x.x`. Записать его.

### За 15 минут до начала

1. Поднять контейнер, если он не запущен:

   ```bash
   docker compose up -d
   ```

2. Открыть презентацию, нажать `F` для полного экрана и проверить,
   что слайды листаются (`→`).

3. Запустить тот же адрес в браузере телефона по Wi-Fi — это проверка,
   что участники смогут подключиться:

   ```
   http://192.168.x.x:8080
   ```

4. Если не открывается — почти всегда файрвол:

   ```bash
   sudo ufw allow 8080/tcp     # для ufw
   sudo firewall-cmd --add-port=8080/tcp   # для firewalld
   ```

5. Отключить автоматический переход ноутбука в сон на время показа.

### Во время

Ссылка для участников — либо GitHub Pages, либо локальная:

```
https://nebolsinvasili.github.io/MS/     # нужен интернет
http://192.168.x.x:8080                  # только внутри той же Wi-Fi сети
```

Если Wi-Fi в аудитории нестабилен, показывайте с ноутбука через Docker:
сайт не обращается в интернет, задержек не будет.

### После

```bash
docker compose down
```

## Доступ из локальной сети

Контейнер слушает `0.0.0.0:8080`, поэтому доступен всем устройствам
в той же сети. Узнать адрес:

```bash
ip -4 addr show scope global | grep -oP 'inet \K[\d.]+' | head -1
```

Открыть на других устройствах: `http://<IP>:8080`.

Учтите: IP по DHCP может смениться после перезагрузки роутера или ноутбука.
Проверяйте его перед каждым показом. Если адрес должен быть постоянным,
лучше зарезервировать его в настройках роутера.

## Публикация на GitHub Pages

Публикация идёт через GitHub Actions — workflow лежит в
`.github/workflows/deploy-pages.yml` и запускается на каждый пуш в `master`.

**Разовая настройка** (без неё workflow не сможет опубликовать сайт):

1. Открыть https://github.com/nebolsinvasili/MS/settings/pages
2. В разделе **Build and deployment** → **Source** выбрать **GitHub Actions**
3. Дождаться первого запуска на вкладке **Actions**

После этого адрес https://nebolsinvasili.github.io/MS/ обновляется
автоматически при каждом пуше.

Workflow публикует только `index.html`, `css/`, `js/` и `assets/` — ноутбук,
README и служебные файлы на сайт не попадают.

Проверить статус последнего деплоя:

```bash
gh run list --limit 5          # если установлен gh
```

---

## Обновление содержимого

| Что меняете | Что делать |
|---|---|
| слайды, стили, скрипты | `docker compose up -d --build` для локальной проверки, затем `git push` |
| картинки | положить в `assets/img/`, пересобрать контейнер |
| шрифты | `python3 scripts/fetch-fonts.py`, затем пересобрать |

После пуша в `master` GitHub Pages обновится сам за 1–2 минуты.

**Важно про кэш:** картинки и шрифты отдаются с `Cache-Control: immutable`
на 30 дней. Если заменить файл, не меняя имя, браузер может показать старую
версию. На показе помогает жёсткое обновление — `Ctrl+Shift+R`
(на Mac `Cmd+Shift+R`).

## Запуск без Docker

```bash
python3 -m http.server 8080
```

Затем открыть http://localhost:8080. Подходит и любой другой статический
сервер (`npx serve`, `php -S`).

Открывать `index.html` напрямую через `file://` не стоит: браузер ограничивает
загрузку локальных ресурсов, и часть слайдов может не отобразиться.

## Управление презентацией

| Клавиша | Действие |
|---|---|
| `→` `↓` `Space` `PgDown` | следующий слайд |
| `←` `↑` `PgUp` | предыдущий слайд |
| `Home` / `End` | первый / последний слайд |
| `O` | режим обзора всех слайдов |
| `F` | полный экран |
| `?` | подсказка по управлению |

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `port is already allocated` | порт 8080 занят: `docker compose down`, либо сменить порт в `docker-compose.yml` на `8081:80` |
| `permission denied ... docker.sock` | нет прав: `sudo usermod -aG docker $USER` и перелогиниться |
| сайт открывается, но без картинок | не дождались сборки: `docker compose logs`, пересоберите `--build` |
| с телефона не открывается | файрвол или разные сети: разрешить 8080, проверить, что устройства в одной Wi-Fi |
| на GitHub Pages 404 | не выбран Source → GitHub Actions в настройках Pages |
| Pages показывает старую версию | кэш: `Ctrl+Shift+R`, либо подождать 1–2 минуты после деплоя |
| шрифт выглядит иначе | шрифты не подгрузились: проверить `assets/fonts/` и `css/fonts.css` |

Диагностика контейнера:

```bash
docker compose ps
docker inspect --format='{{.State.Health.Status}}' ms-deck
docker compose logs --tail 50
```

## Структура репозитория

```
index.html              разметка всех слайдов
css/style.css           оформление
css/fonts.css           подключение локальных шрифтов (генерируется)
js/app.js               навигация, анимации, интерактив
js/digits.js            данные примеров MNIST
assets/img/             изображения к слайдам
assets/tasks/           иллюстрации практических заданий
assets/fonts/           Manrope и JetBrains Mono (woff2)
scripts/fetch-fonts.py  обновление локальных шрифтов
nginx.conf              конфиг nginx для контейнера
Dockerfile              сборка образа
docker-compose.yml      запуск на порту 8080
.github/workflows/      деплой на GitHub Pages
```

Шрифты уже скачаны в `assets/fonts/`. Пересобрать при необходимости:

```bash
python3 scripts/fetch-fonts.py
```

## Примечание про историю git

Из истории репозитория удалена исходная `Презентация.pptx` (19,6 МБ), чтобы
клон оставался лёгким (`.git` ≈ 2,4 МБ). История была переписана, поэтому
у кого есть старый клон — его нужно пересоздать:

```bash
git fetch origin
git reset --hard origin/master
```

Или просто клонировать заново.
